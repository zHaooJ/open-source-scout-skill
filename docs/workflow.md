# 工作流程与设计取舍

[返回首页](../README.md)

本文帮助使用者和贡献者理解 Skill 为什么这样工作。模型的实际执行规则以 [SKILL.md](../SKILL.md) 和它引用的 `references/` 文件为准。

## 从下一步需要什么信息开始

“信息不完整”不一定意味着继续提问。先区分缺的是用户的选择，还是项目的事实。

| 缺口 | 例子 | 处理方式 |
| --- | --- | --- |
| 用户目标 | “知识库”是个人笔记、团队协作，还是资料问答？ | 用能改变检索方向的选择题澄清 |
| 用户取舍 | 接受额外部署服务，还是更希望直接使用完整产品？ | 说明实际差别，再问优先级 |
| 项目事实 | 某项功能是否在开源版？是否仍需外部 API？ | 自行读取官方证据 |
| 次要偏好 | 语言不限，但更喜欢文档丰富的项目 | 记录偏好，继续搜索和比较 |

已经回答过的条件继续沿用。“暂不限”只作用于用户回答的那个维度，例如语言不限不代表许可证也不限。

## 三种可以切换的工作方式

### 探索方向

适合用户只有一个场景或兴趣，还不能判断需要什么。

- 完全没有搜索方向时，先问主要用途。
- 已经能描述问题时，可以先查少量代表路线，让用户看见差别。
- 候选是帮助形成需求的材料，不提前包装成最终推荐。

例如“帮我找个 harness”可能指 Agent 执行框架、模型评测工具或测试设施。应先消除会改变整个搜索方向的歧义。

### 定向搜索

适合目标和基本适用条件已经清楚的任务。

- 根据用途组织查询，不只重复用户原词。
- 区分完整应用、SDK、框架、插件和参考实现，避免只覆盖自己熟悉的类别。
- 用户点名的项目优先核查；如果没有入选，说明具体原因或尚未验证的条件。
- 发现候选后再深入最相关项目，不对所有命中做同等审计。

“先探索”不能用来绕过用户已经明确的硬条件。

### 深入比较

适合用户已有候选，或需要决定先验证哪一个。

- 对各项目回答相同的核心问题。
- 分别说明项目的实际能力、对当前需求的匹配，以及证据把握程度。
- 检查首选推荐理由是否成立，并说明可能改变建议的事实。

例如因“可自托管”推荐一个项目，还需检查其运行数据是否必须发往外部服务；仅发现 Docker 配置不能证明完全离线。

## 选择题如何逐步收紧

优先顺序通常是：**场景 → 使用方式 → 核心能力 → 影响落地的条件 → 实际取舍**。

这不是固定层数。用户已经提供的内容应跳过；无关条件不问。每轮通常 1–2 题，选项表达实际结果，例如“直接部署产品”和“愿意写代码接入”，而不要求用户先懂技术术语。

用户回答“不知道”时，换成例子或实际路线；回答“先搜”时，在其范围内提供探索结果并注明假设。使用异步问答工具时，未回复不代表选中了界面预选项。

完整需求框架见 [intake.md](../references/intake.md)。

## 核验证据的深度

| 层次 | 可以支持的结论 | 不能据此声称 |
| --- | --- | --- |
| 搜索摘要、榜单、博客 | 这个项目值得进一步检查 | 已确认关键功能或许可 |
| 官方文档、许可证、发布说明 | 项目公开说明了哪些能力和条件 | 在用户环境中已成功运行 |
| 相关接口、代码或示例检查 | 对应实现或扩展入口存在 | 目标场景完整可用 |
| 经授权的运行验证 | 指定版本和环境下实际观察到的行为 | 未测试场景也同样成立 |

关键结论保留来源位置和核查日期，涉及版本差异时保留版本。项目声明、模型推断和运行观察分别表达。工具访问失败时，保留未知，不把“没查到”写成“不支持”。

详见 [search-and-evidence.md](../references/search-and-evidence.md)。

## 比较时让用户看懂

先解释每个项目是什么、通常怎样使用，再说明它能为当前任务做什么。

例如“支持向量检索”不足以让用户理解项目。更有用的表述是：“它提供资料索引和检索接口，你需要自己接入模型、设计问答流程和界面。”后一句仍需实际接口与文档支持。

推荐不应只给排名，还应说明：

- 当前优先考虑哪一个，以及决定性理由。
- 什么条件变化时会改选。
- 哪个重要未知尚未解决。
- 哪个最小验证动作能降低采用的不确定性。

详见 [comparison-and-delivery.md](../references/comparison-and-delivery.md)。

## 什么时候结束搜索？

主要路线和关键条件已覆盖，新增搜索不再产生会改变判断的信息时，可以交付。数量不是目标，全面扫完生态也不是完成条件。

只有具体缺口值得扩展检索。例如用户要求离线，而找到的候选都必须调用云服务，可以更换术语、路线或平台；不能偷偷放宽离线要求。

## 收到反馈之后

“这些项目我看不懂”通常意味着应改进简介和共同场景，不意味着重新做一轮问卷。

“我要中文界面”则可能改变候选范围，应更新这个条件并补查相关能力。未受影响的证据可以复用，时间敏感的许可和维护信息按需重新核查。
